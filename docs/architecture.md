# Архитектура

Один процесс бота и один процесс API используют общие сервисы и базу.

- `bot/` — хендлеры, клавиатуры, локали ru/hy/en, состояния регистрации.
- `services/` — подбор, чат, кошелёк, платежи, верификация, рефералы, модерация. Баланс меняет только `services/wallet.py`.
- `database/models` — таблицы пользователей, анкет, сессий, журнала, платежей, жалоб, администраторов.
- `api/` — вход сотрудников, роли, Mini App и webhook.
- `admin/` и `miniapp/` — React. Панель ходит в API с JWT типа `admin`. Mini App получает JWT типа `miniapp` только после проверки подписи Telegram.

Подбор захватывает обоих пользователей условным `UPDATE` в порядке возрастания id, внутри вложенной транзакции. У двух участников одна сессия, поэтому `active_session_id` не уникален на всю таблицу. Повторный поиск и блокировки не создают вторую сессию.

Уведомления пишутся в outbox в той же транзакции, что и деловая операция, и уходят после commit.

Фоновая очистка в боте примерно раз в 30 секунд доставляет outbox, снимает зависший поиск и закрывает молчащие чаты.
